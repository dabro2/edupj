
적응형 => 폭포수 아님. 에자일같은 방식
연동 기획(Rolling Wave Planning)은 프로젝트 관리에서 사용하는 점진적 구체화 기획 기법입

[보안]
정규식 [\\w] : 알파벳(대소문자), 숫자, 언더바만 허용
       {2, 4} 반복회수 2회~4회까지, [ab] : a or b

[소공]
>> 생성패턴
-팩토리 메서드 패턴 : 객체 1개 생성. SMS발송, 카카오톡발송, 이메일발송 각각 별개 인터페이스
-추상 팩토리 패턴 : 관련 객체군(세트) 생성 => 윈도우: 버튼+_텍스트박스+체크박스, 맥:버튼+_텍스트박스+체크박스 그룹 인터페이스
-빌더패턴 : 생성자 매개변수 폭빨 문제 해결. 생성자의 파라미터에 직접 값을 넣으면 향후 파라미터 값들의 의미 파악 어려움. build패턴 가독성을 높여줌/파라미터 순서 실수도 방지.
  => public class User { private String id; private String name; .....; private User(Builder builder) { this.id = builder.id
-프로토타입 패턴 -> 복제해서 만들어세, 바꿀값만 바꿈. cf) 팩토리 -> 만들어 줌, 빌더 -> 조립해서 만듦, 추상팩토리 ->관련된 객체를 세트로 만들어 줌

>> 구조 패턴
- 어뎁터 패턴 : 기존것을 끼워맞춤. 100볼트 -> 어댑처 -> 220볼트
- 브릿지 패턴 : 구현과 추상화(기능)을 분리. TV(구현)와 리모콘(추상화)을 분리. TV제조사마다 리모콘 필요를 없앰
- 데코레이션 패턴 : 기존객체를 수정하지 않고 기능을 동적으로 추가. cf) 스트레티지 패턴 : 기능을 추가하는게 아니라 A를 쓸까 B를 쓸까 동적으로 선택하는 거임
- 컴포지트 패턴 : 트리구조를 동일하게 다루기 위한 패턴. 개별 객체와 객체 그룹을 동일한 방식으로 처리. 
   ex) 회사-개발팀
              ㄴ홍길동
           - 운영팀
              ㄴ김씨네
- 퍼사드패턴 : 복잡한 여러객체들을 감싸고, 단순한 하나의 창구(인터페이스)를 제공하는 패턴. 내부는 복잡, 사용자는 간단하게 사용


>> 행위 패턴
- 옵저버 패턴 : 한객체의 상태가 바뀌면 그 객체를 구독하고 있는 여러 객체에게 자동으로 알려주는 패턴. subject : 관찰대상, Observer : 통지대상
